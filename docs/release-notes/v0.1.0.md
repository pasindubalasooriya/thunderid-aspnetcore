The first release of `ThunderID.AspNetCore`, ThunderID sign-in, API protection and OIDC back-channel
logout for ASP.NET Core.

```
dotnet add package ThunderID.AspNetCore --version 0.1.0
```

Requires .NET 10. Implements the ThunderID SDK specification v0.8. Versions are `0.x` for now,
so a minor version can change the API.

## What's included

- `AddThunderID`: cookie and OpenID Connect sign-in with the authorization code flow, PKCE and a
  nonce.
- `MapThunderIDBackchannelLogout`: receives ThunderID's logout token and refuses that session's
  cookie from the next request. `ILogoutSessionStore` is in memory by default; replace it when
  you run more than one instance.
- `AddThunderIDApi`: JWT bearer for APIs, keeping claim names as they appear in the token.
- `AddScopePolicy`: an authorization policy for ThunderID's space-delimited `scope` claim.
- Checks at startup: the app won't start with a missing or non-HTTPS `Authority`, a missing
  `ClientId` or `Audience`, or settings that turn off PKCE, the nonce, or token issuer,
  audience, lifetime or signature validation.
- The discovery document's `issuer` must exactly match the configured `Authority`, or sign-in,
  logout tokens and API tokens are refused.

## Before you use it

- Back-channel logout needs ThunderID built from `main`; v1.1.0 doesn't include it.
- See [Running in production](https://github.com/pasindubalasooriya/thunderid-aspnetcore#running-in-production)
  and [Limits](https://github.com/pasindubalasooriya/thunderid-aspnetcore#limits). Encrypted
  (JWE) logout tokens, front-channel logout and embedded login aren't supported.
