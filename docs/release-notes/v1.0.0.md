The first stable release. The API is the same as 0.4.0, and from now on it follows semantic
versioning.

```
dotnet add package ThunderID.AspNetCore --version 1.0.0
```

Requires .NET 10. Implements the ThunderID SDK specification v0.9. Nothing is added, removed or
renamed from 0.4.0.

## What 1.0 promises

- Within 1.x, nothing public is removed or changed incompatibly. Minor versions add API, and patch
  versions fix bugs.
- A code in `ThunderIDErrorCodes` never changes what it reports. Minor versions can add codes, so
  a `switch` on `Code` needs a default case.
- Defaults (the scopes requested, `RefreshBeforeExpiry`, the cookie settings, the startup checks)
  and the supported .NET versions change only in a major version.
- The exception is a security fix that can only work by refusing something accepted before. It
  can ship in a minor or patch version, and its notes say what is now refused.

See [Versioning](https://github.com/pasindubalasooriya/thunderid-aspnetcore#versioning).

## What's new

- **IntelliSense docs.** The package now includes `ThunderID.AspNetCore.xml`, so every public
  type and member shows its documentation in the IDE. Earlier packages shipped without it. Every
  public member is documented, and the build fails if one isn't.

## Upgrading

- **From 0.4.0:** change the version. Nothing else changes.
- **From 0.2.0 or earlier:** read the notes for
  [0.3.0](v0.3.0.md) (breaking: every error became a `ThunderIDException` with a code) and
  [0.4.0](v0.4.0.md) (a session now ends when ThunderID refuses its refresh) first.

## Before you use it

- Back-channel logout needs ThunderID built from `main`; v1.1.0 doesn't include it.
- One refresh per refresh token, and the default logout session store, hold within one process.
  With more than one instance, see
  [Limits](https://github.com/pasindubalasooriya/thunderid-aspnetcore#limits).
