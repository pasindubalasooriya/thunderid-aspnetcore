Sign-out now ends the session at ThunderID, and back-channel logout can tell your app which
session ended.

```
dotnet add package ThunderID.AspNetCore --version 0.2.0
```

Requires .NET 10. Implements the ThunderID SDK specification v0.8. No breaking changes from 0.1.0.

## What's new

- `HttpContext.SignOutOfThunderIDAsync(redirectUri)`: revokes the refresh token at ThunderID (or
  the access token, when there's no refresh token), clears the session cookie, then redirects to
  ThunderID's end-session endpoint. If revocation fails, the cookie is still cleared and the
  returned `ThunderIDSignOutResult` reports it, with the reason in `RevocationError`.
- `MapThunderIDBackchannelLogout(pattern, onLoggedOut)`: calls your code with the ended session's
  `sid` and `sub` after the logout is recorded. An exception in the callback is logged, and
  ThunderID still gets `200`.
- An end-to-end suite in the repository: sign-in, sign-up, sign-out with revocation, and
  back-channel logout, run with Playwright every night against a ThunderID built from a pinned
  commit.

## Upgrading

- Replace a sign-out that calls `SignOutAsync` for the cookie and OpenID Connect schemes with
  `HttpContext.SignOutOfThunderIDAsync(redirectUri)`. Don't write to the response afterwards; it
  has already set the redirect.
- For a refresh token to revoke, add `refresh_token` to the app's grant types in ThunderID.
  Without it, sign-out revokes the access token.

## Before you use it

- Back-channel logout needs ThunderID built from `main`; v1.1.0 doesn't include it.
- See [Sign-out](https://github.com/pasindubalasooriya/thunderid-aspnetcore#sign-out),
  [Running in production](https://github.com/pasindubalasooriya/thunderid-aspnetcore#running-in-production)
  and [Limits](https://github.com/pasindubalasooriya/thunderid-aspnetcore#limits).
