The PAR request ASP.NET Core 9 actually sends (captured with a local listener; secret redacted):

POST /par
Content-Type: application/x-www-form-urlencoded

client_id=WItzJCtJA0Ij77xkgHIjKg
redirect_uri=https://localhost:7101/signin-oidc
response_type=code
scope=openid profile email
code_challenge=...&code_challenge_method=S256
response_mode=form_post        <- ASP.NET Core default
nonce=...&state=...
client_secret=<redacted>       <- client_secret_post, no Authorization header

ThunderID's answer to that exact body:
{"error":"invalid_request","error_description":"Unsupported response_mode parameter"}

ThunderID source (backend/internal/oauth/oauth2/constants/constants.go:77):
    return responseMode == "" || responseMode == ResponseModeQuery

Discovery has no response_modes_supported field, so a client can't detect this up front.

Fix in Program.cs:
    options.ResponseMode = "query";
